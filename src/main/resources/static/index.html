⚡ GitHub Actions Self-Hosted Runner Configuration

  • Runner Directory Setup: Create a dedicated directory (e.g., `actions-runner`) in your local machine.
  • Download Package: Fetch the official runner package from GitHub releases using `curl` or browser.
  • Configure Token: Run `./config.sh --url <repository-url> --token <secret-token>` provided by GitHub repository settings.
  • Service & Execution: Start the runner using `./run.sh` or configure it as a background system service for continuous listening.

☸️ Kubernetes & Local Components Required

  • Container Runtime / Docker Desktop: Required for building container images and running local container workloads.
  • Kind (Kubernetes in Docker): To spin up local multi-node or single-node Kubernetes clusters effortlessly.
  • Kubectl CLI: Essential command-line tool for communicating with the cluster API server and managing pods/deployments.
  • Namespaces & Manifests: Configured YAML files for Deployment, Service, and resource constraints (`spring-boot` namespace).

🚀 Argo CD & GitOps Prerequisites

  • Git Repository Structure: Centralized source code and Kubernetes manifests repository for declarative state tracking.
  • Argo CD Controller: Installed inside the Kubernetes cluster to continuously monitor repository changes.
  • Cluster Access & Credentials: Configured target cluster context so Argo CD can sync the desired state automatically.
  • Automated Sync Policies: Optional setup for auto-syncing changes whenever a new image tag is pushed to Docker Hub.
